# Manual Checklist

## Подготовка

1. Запустить backend:

```bash
npm install
npm run dev
```

2. Запустить frontend:

```bash
cd client
npm install
npm run dev
```

3. Если env для admin не заданы, использовать bootstrap admin:

```text
email: admin@example.com
password: admin12345
```

## Сценарий проверки

1. Зарегистрировать нового пользователя через `/register`.
2. Войти под ним и открыть `/me`.
3. Убедиться, что:
   - роль равна `user`
   - доступен список товаров
   - недоступны создание, редактирование и удаление товаров
4. Выйти из аккаунта.
5. Войти под `admin`.
6. Открыть раздел `/users`.
7. Найти созданного пользователя и изменить роль на `seller`.
8. Выйти из `admin`.
9. Войти под этим пользователем снова.
10. Убедиться, что теперь он:
    - видит список товаров
    - может создать товар
    - может открыть товар и отредактировать его
    - не может удалить товар
11. Выйти из аккаунта.
12. Снова войти под `admin`.
13. Открыть созданный товар и удалить его.
14. В разделе `/users` заблокировать пользователя.
15. Проверить, что после блокировки:
    - повторный логин пользователя отклоняется
    - refresh сессии не проходит
    - доступ к защищённым маршрутам больше не работает

## Что ещё проверить вручную

- `guest` видит только `Login` и `Register`
- `admin` видит раздел `Users`
- `/api/auth/me` возвращает `role`
- после `401` frontend пытается обновить access token автоматически
- при ошибке refresh токены очищаются и происходит logout
- после перезапуска backend данные обнуляются, так как проект работает in-memory
